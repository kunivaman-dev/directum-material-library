# Directum Material Library

Статический каталог иконок и продуктовых логотипов Directum, синхронизированный
с библиотеками [иконок](https://www.figma.com/design/nCpoXr1g7y4CP4BNBCIas8/) и
[логотипов](https://www.figma.com/design/FvX1U25kcxavZk0G2nq5HlPd/).

## Как устроены данные

- `public/catalog.js` — единый источник метаданных для сайта: название, категория,
  ключевые слова и варианты.
- `public/assets/variants/<node-id>.svg` — SVG, экспортированные из Figma.
- `public/app.js` — поиск, фильтры, выбор варианта и цвета, SVG/PNG-экспорт,
  копирование SVG и прямых ссылок.
- `public/icons.html` и `public/styles.css` — интерфейс каталога.
- `public/logos-catalog.js` — каталог вариантов логотипов и ссылки на узлы Figma.
- `public/assets/logos/*.svg` — продуктовые логотипы, экспортированные из Figma.
- `public/logos.html`, `public/logos.js`, `public/logos.css` — выбор логотипа по бренду,
  композиции и цветовой версии.
- `app/api/events/route.ts` и `db/` — обезличенные продуктовые события в D1.
- `app/analytics/` — приватный дашборд владельца на маршруте `/analytics`.

Дашборд использует вход через ChatGPT и сверяет пользователя с секретом
`DASHBOARD_OWNER_EMAIL`. Текст поискового запроса сохраняется только для
нулевой выдачи; cookie, IP, user-agent и идентификаторы посетителей не собираются.

На сайте используются категории из поля `category:` в описании компонента Figma.
Если поле не заполнено, иконка попадает в «Без категории». Поиск намеренно не
использует старые свободные строки и автосгенерированные теги: они содержали
нерелевантные значения. Сейчас индекс строится по названию, категории и
`keywords:`. Ключевые слова также показываются в превью каждой иконки.

Одинаковые названия не объединяются: в Figma это разные рисунки. Чтобы карточки
можно было различить, сайт добавляет к ним номера, например «Смайл · 1».

## Проверка

```bash
node test-variants.cjs
node test-logos.cjs
node test-analytics.cjs
python3 scripts/catalog_guard.py check
```

Тест проверяет количество карточек и вариантов, наличие и валидность всех SVG,
набор категорий, поиск по описаниям, отсутствие старого тега «ежедневник» в
индексе и безопасную перекраску одноцветных вариантов.

`test-logos.cjs` проверяет 58 вариантов десяти брендов, уникальность записей,
ссылки на исходные узлы Figma и валидность каждого SVG.

`test-analytics.cjs` проверяет, что обе публикации отправляют события в общий
Sites API, а API принимает CORS-запросы только с двух публичных доменов.

`catalog_guard.py` дополнительно сверяет каталог с последним одобренным
состоянием. Он отдельно показывает добавленные и удалённые иконки, изменения
метаданных и изменения SVG, включая варианты `mono`. После успешной публикации
новое состояние фиксируется командой:

```bash
python3 scripts/catalog_guard.py approve
```

Правила подключения к Figma лежат в `sync/figma-sync.json`. Каталог определяется
без ручного списка: это наборы компонентов с полем `keywords:` и шестью
вариантами свойства «Вид», а также одиночные компоненты с полем `keywords:`.
Поле `category:` необязательно; без него используется «Без категории».
Свободные строки описания намеренно игнорируются.

## Правила обновления

1. Считать из Figma владельцев иконок и только поля `category:`, `keywords:`.
2. Сравнить владельцев, метаданные и SVG с `sync/approved-state.json`.
3. Экспортировать новые и изменённые варианты, включая `mono`.
4. Пересобрать `catalog.js`, не добавляя в поиск свободный legacy-текст.
5. Запустить `node test-variants.cjs` и `python3 scripts/catalog_guard.py check`.
6. Проверить каталог в браузере на desktop и mobile.
7. Только после проверок публиковать новую версию сайта и обновлять одобренное
   состояние командой `python3 scripts/catalog_guard.py approve`.
8. После успешной публикации Sites синхронизировать тот же канонический исходный
   коммит в `kunivaman-dev/directum-material-library`. GitHub Actions обязан
   успешно собрать и опубликовать GitHub Pages; только после проверки обоих
   адресов синхронизация считается завершённой.

## Единая публикация Sites и GitHub Pages

Канонический исходник хранится в репозитории Sites. GitHub содержит его точное
зеркало и не поддерживает отдельную вручную редактируемую копию `dist`.
Workflow `.github/workflows/pages.yml` запускает те же проверки и сборку, затем
`scripts/prepare-github-pages.mjs` формирует статический артефакт для GitHub
Pages. В него входят главная страница, маршруты `/icons` и `/logos`, каталоги и
все SVG-ресурсы. Домен GitHub Pages: `https://directum-design.desserg.ru/`.

Текущий снимок: 239 карточек, 1 184 варианта, 8 категорий с учётом
«Без категории».
